## 这次改了什么、没有改什么

在 `aadcd8e` 这个纯翻译提交中，修改范围是 README、英文自然语言注释、Python
函数说明文字，以及新增中文导读。C++/CUDA 标识符、表达式、launch 配置、模板实参、
校验阈值、脚本命令与运行日志字符串保持原语义。英文 README 另存为
`README.en.md`；LICENSE、原作者版权和原图保留。

注释增多会改变源码行号，`__LINE__` 报错位置和调试行信息因此可能变化，**不声称
二进制逐字节一致**。中文解释未由原作者审核。`aadcd8e` 本身不包含 GPU 性能结论；
后续提交已在 RTX 3080 上独立编译、验证和分析，结果见 04/05 文档。

## 学习时必须知道的上游前提

### 1. 多数优化 kernel 不是任意尺寸 GEMM

1/2 号有输出边界检查；多数后续版本没有通用 M/N/K 尾块屏蔽。`CEIL_DIV` 只是网格向上取整，不会替 kernel 屏蔽越界线程。float4 还要求对齐、有效连续四元素和加载覆盖条件。

11 号 runner 当前 BN=256，而 `sgemm.cu` 从 N=128 开始测试。数学块边界不匹配不能因为底层分配了更大缓冲区就忽略。小尺寸 fallback、7 号固定布局常量也需要独立核对。这里标记为**需单独验证的上游前提**，不混入算法修复。

### 2. bank_calc.py 的上游调用参数问题

上游函数 `printBankConflicts(bank_fun)` 只接收一个参数，底部却额外传入 32/33，直接
执行会触发 `TypeError`。`aadcd8e` 为保持纯翻译没有修改；后续实验修复提交已移除多余
参数，并用 Python 实际执行验证。

### 3. 自动调优不是只读操作

三个 autotuner 都用 `sed -i` 改写 `src/runner.cu`，9 号还改 kernel 中线程常量；它们会清空同名结果文件。9 号固定 `export DEVICE="2"`，在单卡机器上不能靠外部 `DEVICE=0` 覆盖它。

这些脚本只设置 `set -u`，没有完整的退出码/管道错误控制。编译失败、超时或 `tee` 成功不等同于该配置可用。11 号脚本部分过滤条件使用全块线程数，而 runner 的合作搬运使用半块线程数，也应对照检查。不要为了学习一次性启动大范围搜索。

### 4. Makefiles 与 Ninja 不要混用

原 Makefile 和 autotuner 使用子目录 `make`。如果 `build/` 由 Ninja 生成，不能直接套用这套入口。中文 README 的示例明确使用 Unix Makefiles，另行选择 Ninja 时请使用匹配的构建命令与独立构建目录。

上游 CMake 给另外两个演示 target 设置架构时重复写成 `sgemm`；纯翻译提交只作标注，
后续实验修复已分别改为 `cuBLAS_sgemm` 和 `simplest_kernel`。`find_package(CUDA)` 的
新 CMake 兼容问题仍未升级。

### 5. 画图会修改 README，不是单纯导出图片

`gen_benchmark_results.sh` 只跑 0–10，不含 11/12。绘图脚本解析英文性能行，再覆盖 `benchmark_results.png` 和 README 的结果表。它也包含编号/顺序完整性的假设，且没有 12 号标签；只收集任意子集不一定能原样画图。

要长期保留原作者 A6000 表和自己的 3080 表，应分别归档结果，而不是不加标签地覆盖历史数据。中文分支保留英文输出与图表程序标签，避免破坏现有解析。

### 6. 独立 cuBLAS 演示与 helper 的细节

`cuBLAS_sgemm.cu` 当前是 2×3 乘 3×4 的打印演示，没有性能计时循环。A 的打印表达式使用 `i*m+j`，与行主序 `[m,k]` 的常规跨度 `i*k+j` 不同；本分支标注但没有修复。

上游 `runner.cuh` 声明 `get_current_sec()`，`runner.cu` 定义 `get_sec()`；后续修复已
统一为前者。主 benchmark 仍使用 CUDA Event，此 helper 不参与 GPU 计时。

### 7. 原 benchmark 的测量口径

历史入口的尺寸为 128、256、512、1024、2048、4096，重复 50 次，alpha=0.5、
beta=3.0。计时循环不会每次重置 C，所以会连续执行 `C=alpha*AB+beta*C`；在
`beta=3` 下它不是稳定的重复输入。为保留旧数据，默认行为没有删除。

后续新增的公平入口使用 `SGEMM_RESET_C_EACH_REPEAT=1`，在每次 CUDA Event 开始前
用 D2D copy 恢复同一份 C，copy 不计入 GEMM 时间；`SGEMM_SEED` 固定 A/B/C。kernel
13 是 pedantic FP32 cuBLAS，kernel 14 是显式 TF32 对照。两种口径必须分别标注。

未设置 `SGEMM_SEED` 时仍沿用时间种子。校验继续使用上游绝对误差 0.01 并检查 NaN；
本次没有放宽阈值。固定 seed 的通过结果只证明所列输入与尺寸，不是全面数值证明。

4096×4096 的单个 FP32 矩阵占 64 MiB，主程序分配 A/B/C/C_ref 四份 GPU 缓冲区，共约 256 MiB，另有运行库开销。这里是按代码计算的容量，不是实测显存峰值。

## 如何验证中文分支没有混入代码改动

固定上游版本为 `5a7dcc513d951ba764d51bc9d587b3163f3a894d`，固定纯翻译版本为
`aadcd8e75a20bec58a7229da6f4d40a4d6df26a4`。不要用后续性能提交的 HEAD 代替纯翻译
版本。在自己的 clone 中检查：

```bash
git status --short
git diff --stat 5a7dcc513d951ba764d51bc9d587b3163f3a894d..aadcd8e
git diff 5a7dcc513d951ba764d51bc9d587b3163f3a894d..aadcd8e -- src sgemm.cu CMakeLists.txt scripts

# 原许可证应相同，英文备份应与原 README 相同。
git diff 5a7dcc513d951ba764d51bc9d587b3163f3a894d..aadcd8e -- LICENSE
```

不能只按“删除所有 // 后文本”比较 C++，因为字符串/URL/转义也可能包含注释符号。Python 要区分普通字符串与说明用 docstring。脚本的 shebang、Makefile 制表符和续行也需要保留。

可以运行新增的只读静态检查器：

```bash
python3 scripts/verify_zh_translation.py
```

它直接读取上游 commit 与 `aadcd8e` 的 Git blob，不读取当前工作树来判定翻译纯度。
因此后续真实算法改动不会被误报成翻译失败。检查覆盖原文件列表、英文 README 备份、
C++ 非注释 token、Python 去说明文本后的 AST，以及 shell/构建配置的非注释文本。
**静态检查通过不等于编译或 GPU correctness 通过**。

GPU 验证、精度分流和公平计时命令见 05 文档。修复上游问题时应保留独立证据与历史
数据，不得为了得到 PASS 而调低阈值。
