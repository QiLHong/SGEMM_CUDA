# 02：从 shared memory 到 warp tiling 与流水线

> 新增学习补充；说明依据对应 kernel 和 `src/runner.cu`。以下描述优化动机，不替代本机测量，也不承诺每一步都会加速。

## 参数统一看成“谁负责多少输出”

| 名称 | 含义 |
|---|---|
| M/N/K | 完整矩阵的行、列与归约维度 |
| BM/BN | 一个 block 负责的 C 区域大小 |
| BK | 每次共享缓存覆盖的 K 长度 |
| TM/TN | 一个线程在一片区域里负责的行数/列数 |
| WM/WN | 10–12 号中一个 warp 负责的连续输出区域 |
| WMITER/WNITER | 一个 warp 区域沿 M/N 拆成的子区域数 |
| WSUBM/WSUBN | 这些 warp 子区域的大小 |

9 号原代码也使用 `WM/WN` 和 warptile 命名，但其 `16×16` 线程位置铺的是整个 256-thread block 的区域，不是单个 32-thread warp。不要仅凭变量名推断线程所有权。

## Kernel 3：全块合作搬运，共享重复使用

```text
A 全局子块 [BM,BK] ─┐
                    ├─ shared memory ─→ 多个线程重复读取 ─→ C 子块
B 全局子块 [BK,BN] ─┘
```

3 号中三者边长都是 BLOCKSIZE，每线程搬一个 A 和一个 B，再计算自己的一个 C。A 子块中的值可被多个输出列复用，B 子块中的值可被多个输出行复用。

第一道 `__syncthreads()` 防止有人读到还没搬完的数据；第二道防止快线程在慢线程仍计算时覆盖当前缓存。它们解决的是**准备完成**与**消费完成**两种不同依赖。

## Kernel 4/5：共享缓存之后，再做寄存器复用

4 号每线程计算同一列的 TM 个结果。固定 `dotIdx` 先读取一个 `tmpB`，再与 TM 个 A 值相乘。这样这个 B 值不必为每个结果重新加载。

5 号每线程计算 TM×TN 个结果：读取 TM 个 A、TN 个 B，做一次外积：

```text
regM[TM] × regN[TN] → TM*TN 次乘加
```

所以读入 TM+TN 个标量即可更新 TM*TN 个累加器，而不是每个结果都单独读取两次。代价是更多寄存器与更复杂的线程分工；寄存器不足可能导致 spill 或限制驻留线程块数。源码数组声明表达了线程私有存储，实际寄存器分配仍由编译器决定。

## Kernel 6：float4 和 shared memory 转置

`float4` 是四个 FP32 的组合，合计 16 字节；它不是 FP16，也不是 Tensor Core 运算。使用它表达向量化读写，必须满足对齐和连续有效元素条件。

6 号读取 A 的连续四个元素，然后按 `As[k*BM+row]` 写入共享内存。**完整矩阵 A 没有转置**，改变的是片上子块布局。这样计算时同一 k 对应的多个 A 行在 shared memory 中连续。

理解布局时要同时写出两个公式：“如何写 As”与“如何读 As”。只看其中一个，很容易把转置理解反了。

## Kernel 7/8：global coalescing 与 shared bank 不是同一个问题

global memory 连续访问不代表 shared memory 必然无冲突。对本教程的 FP32 bank 推导，可按 `(字节地址/4) mod 32` 观察 lane 分布。多个线程读取同一个字的广播，不应误算成不同字的 bank 冲突。

7 号重排 Bs，使特定计算访问映射到更合适的 bank；实现含固定的 8/16 布局常量。8 号给 Bs 每行加 `extraCols=5`，改变行跨度，让行起点的 bank 分布发生变化。padding 不属于数学上的输出元素。

两者都有额外地址/存储代价，原作者结果中并非一定比 6 号快。优化应比较总耗时，不能只看某一项 bank 指标。

## Kernel 9/10：自动调优与真实 warp 分工

9 号的参数由外部脚本枚举，再修改源码、编译并运行。`sgemmAutotuned` 本身没有运行时搜索循环。读完参数约束再试调优，否则可能只是在测试不合法布局。

10 号明确分出 warpIdx、warpRow/Col，再把 lane 映射到 warp 子区域。一个重要覆盖关系是：

```text
32 * TM * TN * WMITER * WNITER = WM * WN
```

当前 runner 的 10 号配置：BM=BN=128，WM=WN=64，128 个线程即 4 个 warp。每个 warp 占一个 64×64 输出区，四个区域铺满 128×128。TM=8、TN=4、WNITER=4 时，WMITER=1；每个线程共负责 128 个输出。不要照抄源注释中的其他示例数值替代实际参数。

Grid 轴与较早版本也有区别：1–3 号 grid.x 对应行块，4–12 号 grid.x 对应列块。block 的实际执行顺序不是由编号连续性保证的；原作者关于 L2 局部性的性能观察应理解为特定配置下的测量解释。

## Kernel 11：两组线程和两个共享槽

11 号用双份 As/Bs，线程分成前后两组。前组计算当前槽时，后组尝试加载下一槽；接着交错计算和后续加载。每组都负责自己的 warp 输出，并不是“加载组永远不计算”。

理解它需要画出两个线程组各自的时间线，标出每个屏障和每次覆盖。分支内同步尤其不能照搬为通用模板。当前 runner 的 BN=256 与主程序的 N=128 起始测试存在尺寸前提问题，本分支仅标注，不修复或认证该实验实现。

## Kernel 12：异步复制与 barrier

12 号通过 `cuda::memcpy_async` 提交下一槽复制，等待 front barrier 后计算当前槽，再交换槽号和对应 barrier。最后一次计算是流水排空。

```text
预热：提交第 0 块
循环：提交下一块 → 等当前块就绪 → 计算当前块 → 交换槽/屏障
排空：等待并计算最后一块
```

复制提交返回不等于数据已经就绪；`aligned_size_t` 也只是对齐约定，不会自动修复坏地址。异步复制与计算是否有效重叠，需要分析和测量，不是写出双缓冲就必然提速。

## 读完后应该能解释

为什么同样的矩阵乘法，减少 global memory 流量还不够，还需要考虑 shared memory 访问、寄存器复用、线程所有权、对齐、资源占用与同步？

解释这些时，尽量用“谁读哪个地址、谁复用这个值、什么时候才能覆盖”来描述，而不是只说“用了高级优化”。
