# 01：矩阵索引与线程映射

> 新增学习补充。用本仓库 1/2 号 kernel 的具体表达式推导，不改变它们的实现。

## 形状先于指针

```text
A：M 行 K 列
B：K 行 N 列
C：M 行 N 列
C[row,col] = alpha * sum(A[row,k] * B[k,col]) + beta * C[row,col]
```

行主序数组每行连续。二维地址展平成一维时：

```text
A[row,k]   → A[row*K + k]
B[k,col]   → B[k*N + col]
C[row,col] → C[row*N + col]
```

这里 `K/N` 是各矩阵的完整行跨度，不是 tile 大小。比如 `A` 有 3 列，`A[1,2]` 的偏移就是 `1*3+2=5`。指针加 1 表示跨过一个元素，不是跨过 1 字节。

## thread、block、grid、warp

一个 kernel launch 指定一个 grid，grid 由多个 block 组成，block 内有多个 thread。`blockIdx` 决定块编号，`threadIdx` 决定块内线程编号。对于本教程目标 NVIDIA 架构，warp 是 32 个线程的执行分组，不等同于整个 block。

二维 block 的线性线程编号按 x 优先展开：`tid = threadIdx.x + blockDim.x * threadIdx.y`（忽略本例没有使用的 z）。这意味着 `blockDim=(32,32)` 时，同一 warp 的 x 连续、y 相同。

硬件概念可参考 [CUDA Programming Guide](https://docs.nvidia.com/cuda/cuda-c-programming-guide/index.html)。不要把源码中的变量名 `x`、`y` 自动等同于矩阵的列和行，必须看赋值表达式。

## Kernel 1：一条 warp 沿输出的行方向排列

[原实现](../../src/kernels/1_naive.cuh) 定义：

```cpp
x = blockIdx.x * blockDim.x + threadIdx.x;
y = blockIdx.y * blockDim.y + threadIdx.y;
```

`x` 是 C 的行，`y` 是 C 的列。runner 使用 `blockDim=(32,32)`。在第一个 block、第一条 warp 中：

```text
lane       0       1       2       ... 31
输出       C[0,0]  C[1,0]  C[2,0]  ... C[31,0]
固定k读A   A[0,k]  A[1,k]  A[2,k]  ... A[31,k]
固定k读B   B[k,0]  B[k,0]  B[k,0]  ... B[k,0]
```

A 地址相差 K 个 float，C 写回地址相差 N 个 float。单个线程沿 K 走时读 A 是连续的，但**合并访问考察的是一个 warp 中各线程在同一条访问上的地址**，不能只观察一个线程自己的循环。

## Kernel 2：让相邻 lane 对应相邻列

[2 号实现](../../src/kernels/2_kernel_global_mem_coalesce.cuh) 用一维 block：

```cpp
cRow = blockIdx.x * BLOCKSIZE + threadIdx.x / BLOCKSIZE;
cCol = blockIdx.y * BLOCKSIZE + threadIdx.x % BLOCKSIZE;
```

当前 `BLOCKSIZE=32`，所以第一个 warp 变为：

```text
lane       0       1       2       ... 31
输出       C[0,0]  C[0,1]  C[0,2]  ... C[0,31]
固定k读A   A[0,k]  A[0,k]  A[0,k]  ... A[0,k]
固定k读B   B[k,0]  B[k,1]  B[k,2]  ... B[k,31]
```

A 是同地址读取，B 和 C 是连续地址访问。这有利于合并内存请求，但不表示“所有访问必然只有一个物理事务”；对齐、访问宽度与硬件都会影响事务划分。

两个 kernel 的每线程乘加次数仍为 K，数学结果不因线程映射而改变。优化点首先是**谁在同一时刻访问相邻元素**。

## 边界与 tile quantization

1/2 号含有 `row<M && col<N` 检查。原因是 grid 往往按 `ceil(M/tile)`、`ceil(N/tile)` 启动，最后一个 block 可能覆盖超出矩阵的线程。

原注释的 `tile quantization` 在这里指尺寸按整块离散化/取整的效应，和你在 vLLM-LiteQ 里看到的 INT8/INT4 权重量化不是一回事。

3 号之后的很多实现**没有这些通用检查**。即便 runner 使用向上取整，也不代表 kernel 能安全处理任意 M/N/K。

## cuBLAS 为什么交换 A/B？

自写 kernel 按行主序存储，而 [runner 的 cuBLAS 调用](../../src/runner.cu) 使用列主序 API。相同的行主序 A 内存，按列主序解释就对应 A 的转置。利用：

```text
(A*B)^T = B^T*A^T
```

可交换操作数并交换输出维度，让同一内存写出所需的行主序结果。这里不是“先生成两份完整转置矩阵”，而是调整 API 对内存布局的解释和 leading dimension。

2. 为什么 Kernel 1 中“单线程连续读 A”不能证明 warp 的 A 访问连续？
3. `C[row*N+col]` 里的 N 为什么不能随意换成 BN？
4. β 不为 0 时，两条正确性对照路径为什么必须从相同的旧 C 开始？

核对前两个索引：31→(0,31)，32→(1,0)，33→(1,1)。其余问题请先用矩阵形状和地址公式自己解释。
