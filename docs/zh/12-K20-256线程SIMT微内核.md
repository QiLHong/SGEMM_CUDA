# K20：256-thread、256×128 FP32 SIMT 微内核实验

日期：2026-10-12

编译目标：SM86、CUDA 12.4；目标运行机器为 RTX 3080。

## 1. 这轮真正验证什么

strict FP32 cuBLAS 在既有 Nsight 审计中选择了
`cutlass_80_simt_sgemm_256x128_8x4_nn_align1`。K20 因此不再给 K10 叠加局部技巧，
而是新建 256 threads、`BM=256, BN=128, BK=16` 的纯 CUDA Core SIMT kernel。
K10 不改、默认 kernel 不改，K20 只通过编号 20 调用。

要避免一个错误推论：

```text
256 × 128 outputs / 256 threads = 128 outputs/thread
```

它只是在“整个 CTA tile 一次遍历 K，并让全部结果同时驻留”的条件下，说明平均需要
128 个 accumulator。它不是任意实现的寄存器下限。可以分割 warp tile、分阶段遍历 K、
分批 epilogue；代价则是重复搬运、同步、地址计算，或额外 workspace/reduction。

因此本轮同时保留 one-pass 和 phased 两类设计，不把 `256×128` 字面等同于 128 个常驻
accumulator。

## 2. 三个受控版本

共同参数：

| 参数 | 值 |
|---|---:|
| CTA tile | 256×128×16 |
| threads / warps | 256 / 8 |
| A shared layout | `As[16][260]`，即 `AS_PAD=4` |
| B shared layout | `Bs[16][128]` |
| static shared | 24,832 B |
| global load | float4 |
| Tensor Core / WMMA / MMA | 不使用 |
| cp.async / shared double buffer | 不使用 |

### V1：one-pass 64×64 warp tile

8 个 warp 按 4 行×2 列覆盖 CTA：

```text
N:        0..63       64..127
M 0..63    W0            W1
 64..127   W2            W3
128..191   W4            W5
192..255   W6            W7
```

每个 lane 的 fragment 为 8 行×16 列，即 128 accumulator。参数为
`WM=64, WN=64, WNITER=4, TM=8, TN=4`。

### V2：one-pass 128×32 warp tile

8 个 warp 按 2 行×4 列覆盖 CTA：

```text
N:        0..31  32..63  64..95  96..127
M 0..127    W0      W1      W2       W3
128..255    W4      W5      W6       W7
```

每个 lane 仍是 128 accumulator，但 fragment 变成 16 行×8 列。参数为
`WM=128, WN=32, WNITER=2, WMITER=2, TM=8, TN=4`。

### V3：两阶段 64×32 warp tile

V3 保留 V2 的 2×4 warp 所有权，每个 warp 的最终区域仍是 128×32，但分成两个
64×32 阶段：

```text
phase 0: 每个 warp 计算其所有权区的上半 64×32，完整遍历 K，写回
phase 1: 每个 warp 计算其所有权区的下半 64×32，完整遍历 K，写回
```

每阶段每线程只有 8×8=64 accumulator。每个 C 元素仍按 `k=0..K-1` 原顺序累加，
且只执行一次 `alpha*acc + beta*C`，所以没有用改变浮点顺序或 beta 语义换寄存器。

代价也不能隐藏：每个阶段都重新加载完整 `A[256×16]` 和 `B[16×128]` tile，global
搬运与 block barrier 翻倍；shared→register 的动态 LDS 从 one-pass 的 96 条/线程主体
增加到约 128 条/线程（64 条阶段体执行两次）。V3 是明确的 occupancy/重复工作交换，
不是默认更优方案。

## 3. 边界与正确性设计

4096 等 `M%256==0` 尺寸启动无边界分支的 fast 实例。六尺寸中的 128 使用独立
`EDGE_M=true` 实例：A 越界行写零，所有线程仍参加 barrier，无效 warp 只在该阶段全部
barrier 结束后跳过 C epilogue。没有回退到 K10。

当前 V1/V3 要求 `M%64==0`，V2 要求 `M%128==0`；三者还要求 `N%128==0,
K%16==0`。这覆盖规定的 128/256/512/1024/2048/4096，但不把 K20 描述成任意
尺寸 GEMM。

## 4. 已测的编译资源

以下来自本仓库 CUDA 12.4、`sm_86` Release 编译的 ptxas 输出，不是 Nsight 运行数据：

| 版本 | fast registers/thread | shared | spill | 基于资源上限可驻留 block/SM | warps/SM |
|---|---:|---:|---:|---:|---:|
| K10 | 184 | 16,640 B | 0 | 2 | 8 |
| K20 V1 | 184 | 24,832 B | 0 | 1 | 8 |
| K20 V2 | 184 | 24,832 B | 0 | 1 | 8 |
| K20 V3 | 126 | 24,832 B | 0 | 2 | 16 |

V1/V2 虽把 threads/block 加倍，却没有增加每 SM 的 resident warp 数：K10 是两个 4-warp
CTA，V1/V2 是一个 8-warp CTA。它们真正改变的是 CTA 内数据复用和调度域。V3 才可能
把 resident warp 提到 16；“可能”仍需用 NCU 的 achieved occupancy 与 eligible warp
验证，不能由静态资源直接宣称实际 latency hiding 已改善。

cuBLAS 审计值约 202 registers/thread、50 KB shared，说明它自己也更像一个 8-warp、
低 occupancy 但 pipeline 很强的整体设计。V3 不等于复制 cuBLAS，而是验证另一条合法
资源平衡曲线。

完整资源表见
[sm86-k20-static-resources-20261012.csv](../results/sm86-k20-static-resources-20261012.csv)。

## 5. 静态 SASS

| 模式 | 静态 FFMA | LDS | IMAD | IADD3 | LEA |
|---|---:|---:|---:|---:|---:|
| K10 | 2176 | 96 | 20 | 26 | 22 |
| V1 | 2176 | 96 | 12 | 28 | 23 |
| V2 | 2176 | 96 | 12 | 45 | 40 |
| V3 单阶段循环体 | 1088 | 64 | 12 | 31 | 24 |

V1 在静态整数地址指令上比 V2 简单；V2 的二维 128×32 fragment 带来更多 IADD3/LEA。
V3 的 phase 循环体运行两次，因此不能把表中的 1088 FFMA 误读成少算一半；动态 FFMA
仍与其他版本相同，而动态 LDS 和 global tile load 更多。完整表与 SASS hash 见
[sm86-k20-static-sass-20261012.csv](../results/sm86-k20-static-sass-20261012.csv)。

## 8. 如何回答核心问题

在运行数据缺失时只能给出判别规则：

- 若 V1/V2 明显提高 issue/FMA 且 no-eligible 降低，说明更大的 CTA 复用/调度域是 K10
  缺失因素；V1 胜 V2 更可能指向较低地址成本，V2 胜则指向 fragment 形状。
- 若 V3 用 16 resident warps 降低 no-eligible，但 GFLOPS 仍下降，说明重复 global/shared
  路径与 barrier 成本超过 occupancy 收益；不能再用“提高 occupancy”解释方向。
- 若三者都不胜 K10，则单独放大 CTA 不是剩余 9% 的答案。cuBLAS 的优势更应归到
  约 50 KB shared 的成熟多阶段 pipeline、iterator 与 SASS scheduling 的整体组合，而不是
  “256 threads”这个表面参数。
- 只有 GFLOPS、issue slots、FP32 pipe、eligible/no-eligible、spill 与 SASS 解释同时成立，
  才接受 K20；否则保留 K10 为默认。
