# 第 4 章 分块与寄存器小矩阵

[上一章](03-访存与数据复用.md) · [目录](README.md) · [下一章](05-Warp与Shared映射.md)

分块不是改变矩阵乘法，而是重新安排数据的保留范围。本章把 block、K 分段和
线程外积串起来，解释为什么 GEMM 不是“一个线程一个输出”就结束了。

## 1 先在小矩阵上切 K

回到第一章的 A[2,3] 与 B[3,2]。若一次只处理 BK=2 个 k，先处理 k=0、1：

```text
第一段部分和 P0 = [25 28]
                  [73 82]

第二段 k=2 的贡献 P1 = [33 36]
                      [66 72]

P0 + P1 = [ 58  64]
          [139 154]
```

最后一段只有一个有效 k。教学实现可以按实际边界处理；高速研究 kernel 可能
要求 K 为 BK 的整数倍。不能把 CPU 练习支持尾部，推论成 K30 也支持任意尾部。

最容易犯的错，是每进入一个 K tile 都把 accumulator 清零。acc 必须在整个
K traversal 中保留，直到所有段算完，才能执行一次 alpha/beta epilogue。

## 2 Block tile 控制合作范围

BM×BN 表示一个 CTA 负责的输出区域。CTA 和 block 在本书场景中指同一合作层级。
每一段 K 需要 BM×BK 的 A tile、BK×BN 的 B tile，生成 `BM*BN*BK` 次 FMA。

假设 BM=BN=BK=2：四个输出需要每个 k 的四次 FMA。将两个 A 和两个 B 读入后，
就可组合更新四个结果，而不是为每个结果重新从 global 请求一对输入。
省的是重复需求，数学工作量仍相同。

## 3 从块内共享到线程内外积

block 在 shared 复用数据之后，还可以让一个线程负责多行多列。例如 TM=2、TN=3：

```text
线程先加载 a0,a1 和 b0,b1,b2
acc00 += a0*b0   acc01 += a0*b1   acc02 += a0*b2
acc10 += a1*b0   acc11 += a1*b1   acc12 += a1*b2
```

只装载 5 个输入标量，就更新 6 个 accumulator。一般情况装载 TM+TN 个输入，
执行 TM*TN 次 FMA。这叫外积式更新；它把一次点积循环组织成一系列小外积。

这不是免费午餐：结果一直存在寄存器中，TM/TN 增大后，寄存器和寻址成本都可能
上升。源码数组也不保证编译器能全部放入寄存器，必须检查分配和 spill。

## 4 为什么不同尺寸不能只比较一个参数

BM/BN 变大可能增加复用，却也增加输出状态；BK 变大减少 K 循环轮数，却增加
单 stage shared，可能改变展开和加载调度。相同 CTA 下增加 stage 又会继续
增加 shared。它们会共同限制可以驻留多少 block。

以 K30 V2 的真实布局计算用户 shared：

```text
A stage: BK*(BM+4) = 16*132 个 float
B stage: BK*BN    = 16*128 个 float
两 stage: 2*(16*132+16*128)*4 = 33,280 字节
```

这只是源码显式请求的 shared。Profiler 的整块资源口径可能包含额外开销，
不要把不同口径的数字直接当作矛盾。

## 5 简单算术强度推导

只计一个 CTA 阶段的 A/B global 逻辑输入，忽略 C 与 padding，并假设每份输入
在该阶段只搬一次：

```text
FLOP = 2*BM*BN*BK
byte = 4*(BM*BK+BK*BN)
强度 = BM*BN / (2*(BM+BN))
```

BM=BN=128 得 32 FLOP/byte，BK 在这个简化式里约掉了。这不是说 BK 不影响
性能，而是说这个模型没包含同步、shared 服务、资源驻留和指令成本。
一个模型里看不到的因素，不等于真实硬件里不存在。

## 6 源码精读：K5 如何把一个线程变成一个小矩阵乘法器

先打开 [runSgemm2DBlocktiling](../../../src/runner.cu#L247)，再打开
[K5](../../../src/kernels/5_kernel_2D_blocktiling.cuh#L17)。对本书使用的整除大尺寸，
实际参数是 BM=BN=128、BK=8、TM=TN=8，线程数为 `128*128/(8*8)=256`。
不要把第五章的 K30 参数直接代入这里。

K5 分成两套线程坐标。第一套决定**计算所有权**：

```cpp
const int threadCol = threadIdx.x % (BN / TN);
const int threadRow = threadIdx.x / (BN / TN);
```

tid=17 时，threadRow=1、threadCol=1，因此负责 tile 内行 8..15、列 8..15。
三个局部数组分别是：

```cpp
float threadResults[TM * TN] = {0.0};
float regM[TM] = {0.0};
float regN[TN] = {0.0};
```

结果数组有 64 项，输入片段各 8 项。每个 dotIdx，K5 先从 shared 抽出 A 的
8 行、B 的 8 列，再执行下面的实际更新：

```cpp
threadResults[resIdxM * TN + resIdxN] += regM[resIdxM] * regN[resIdxN];
```

令 resIdxM=2、resIdxN=3，则结果数组下标为 19，对应 tile 内 C[10,11]。
dotIdx=5 时，这一次更新用 A[10,5]×B[5,11]；下一 dotIdx 更新的仍是结果 19，
但输入换成下一对。每个 k 有 64 个不同 accumulator 可以更新，并非把所有
乘积都串在同一个 tmp 上。这提供了独立工作的空间，但实际指令调度仍由编译结果决定。

### 6.1 搬运坐标不是输出坐标

第二套坐标负责把 A/B 搬进 shared：

```text
innerRowA = tid / BK       innerColA = tid % BK
strideA = 256 / BK = 32
innerRowB = tid / BN       innerColB = tid % BN
strideB = 256 / BN = 2
```

tid=17 因此搬运：

|对象|本段搬运的逻辑位置|为什么有多项|
|---|---|---|
|A|行 2、34、66、98，K 列 1|loadOffset 沿 M 以 32 前进|
|B|K 行 0、2、4、6，列 17|loadOffset 沿 K 以 2 前进|
|C 输出|行 8..15 与列 8..15 的笛卡尔积|由 threadRow/threadCol 决定|

它搬运的 A 行 2 并不属于自己输出的行 8..15。这是有意设计：搬运布局服务于
协同访存，计算布局服务于数据复用，两者通过 shared 交接。

### 6.2 一次真正的完整地址推导

取 M=N=K=256、blockIdx.x=1、blockIdx.y=0、tid=17。
此 block 输出全局行 0..127、列 128..255。上面的 threadResults[19] 最终属于
全局 C[10,139]，一维偏移 `10*256+139=2699`。

在第二段 K（从 k0=8 开始）、dotIdx=5 时，它累加的是
A[10,13]×B[13,139]。注意三种“列宽”：A 的 global 跨度为 256，A shared
行跨度为 BK=8，threadResults 行跨度为 TN=8。后两者这次数值相同只是巧合，
含义不同，不能互相替换。

### 6.3 用变量作用域看生命周期

沿 K5 源码从上向下标记：threadResults 在最外层 K 循环前清零；regM/regN 在
每次 dotIdx 装入新值；shared 在每次 block K tile 被覆盖；epilogue 在整个 K
循环结束后才读取旧 C 并应用 alpha/beta。

数组有 64+8+8=80 个 float，并不意味着编译报告必然是 80 registers/thread：
地址、指针、临时值也要资源，编译器还会复用、重排或溢出。这是第七章必须检查
ptxas 而不是只数源码变量的原因。

## 7 练习

1. 第一章例子 BK=2 时，为什么第二段还要加到第一段的 acc 上？
2. TM=4、TN=8，每个 k 读几个标量、更新几个结果、完成几个 FLOP？
3. K=4096，BK=16 与 BK=8 分别需要多少段？后者是不是天然更慢？

### 参考答案

1. 每段只覆盖点积的部分项，必须保留所有部分和。清零会只留下最后一段。
2. 输入 12 个标量，32 个结果，32 次 FMA，即 64 FLOP；不计访存和寻址指令。
3. 分别 256 与 512 段。不能直接判断，较小 BK 同时改变资源、流水和同步成本，
   需要一致口径测量。本项目单独改变 BK/stage 没有自动复制 cuBLAS 的效率。

练习脚本的 `test_k_tiling` 用相同 k 累加顺序检查分段数学等价性。

[K30](../../../src/kernels/30_kernel_mini_simt.cuh) 的 Shape、compute 和 epilogue。
